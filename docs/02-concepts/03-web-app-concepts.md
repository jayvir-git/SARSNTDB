# Web application concepts

A minimal overview of how SARSNTDB works as a web app, for readers without a strong web-development background.

## Request–response

1. You type a URL (e.g. `http://localhost/SARSNTDB/GenomeSearch.php`) or click a link/button that submits a form.
2. The **browser** sends an **HTTP request** to the server (Apache).
3. The **server** runs the **PHP** script (e.g. `GenomeSearch.php`). PHP can:
   - Read **GET** or **POST** parameters (e.g. Start, End, Protein).
   - Connect to the **database** and run queries.
   - Build **HTML** (and include CSS/JS references) and send it back.
4. The **browser** receives the **HTTP response** (HTML page) and displays it.

So each page you see is generated by a PHP script that may use the database and then outputs HTML.

## Server-side vs client-side

- **Server-side (PHP):** Runs on the server. Connects to the database, builds queries, and produces HTML. The user never sees the PHP code, only the resulting page.
- **Client-side (HTML, CSS, JavaScript/jQuery):** Runs in the browser. Handles clicks, form validation, and **AJAX** calls (requests that fetch more data without reloading the whole page). For example, when you select a protein and the page updates a table or chart, that may be done via JavaScript calling a PHP endpoint (e.g. `GenomeComparisonData.php?Protein=...`) and then inserting the returned HTML or data into the page.

## Include and require

- PHP can **include** or **require** other PHP files. So one page might do:
  - `include "Navigation.php";` → inserts the navigation bar (HTML + any PHP inside it).
  - `require_once './connection.php';` → loads the database connection (`$con`) once.
- This way, **Navigation.php** and **connection.php** are shared across many pages. Changing the nav or DB config in one place affects all pages that include them.

## URLs and parameters

- **GET parameters** appear in the URL after `?`: e.g. `GenomeResult.php?Start=21563&End=25384&Protein=Surface+Glycoprotein`. PHP reads these with `$_GET['Start']`, `$_GET['End']`, etc.
- **POST** is used when a form is submitted with method POST; data is in the request body, not the URL. PHP reads it with `$_POST['fieldname']`.
- The app uses GET for many search links so that a result page can be bookmarked or refreshed with the same parameters.

## Sessions (for sequence search)

- When you search by **DNA sequence**, the app may store the list of match positions in a **session** (server-side storage tied to your browser). The next page can then show “Sequence Search Results” with those positions. Session variables are accessed in PHP with `$_SESSION['key']`.

## Static assets

- **CSS** (e.g. `style.css`, `bootstrap.css`) and **JavaScript** (e.g. `main.js`, CanvasJS) are **static files**. The browser requests them by URL (e.g. `style.css`); the server sends the file as-is. They are not executed as PHP.
- **Images** (e.g. in `img/`, `helpimages/`) are also static. Referenced in HTML with `<img src="helpimages/fig1.png">` etc.
